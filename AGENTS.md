# AGENTS.md

Guidance for AI coding agents working in this repository.

## Project overview

Football transfer dashboard ("Transfer Radar"): a native Node.js server that proxies the Sportmonks Football API, normalizes confirmed transfers and rumours, and serves a React frontend built with Vite. When no API token is configured, or when the upstream fails and fallback is enabled, the app serves clearly labeled demo data.

- **Server runtime:** Node.js >= 18 (uses the built-in `fetch`); no third-party npm runtime dependencies
- **Frontend:** React 19 + Vite 6 (JSX, no TypeScript)
- **Build output:** `dist/` (Git-ignored; required at runtime)
- **Package manager:** npm; `npm install` is required for the frontend build
- **UI language:** Simplified Chinese (`zh-CN`); code identifiers and comments are English

## Commands

```bash
npm install      # install React/Vite build dependencies
npm start        # build, then start on http://127.0.0.1:4173 (demo mode without a token)
npm run dev      # Vite dev server on :5173, proxies /api to :4173
npm run dev:api  # Node API only; requires a previous npm run build
npm run build    # production build into dist/
npm run check    # Vite build + node --check on server/scripts/tests
npm test         # Vite build, then smoke tests and unit tests
```

Run both `npm run check` and `npm test` after any change. Tests use random free ports, a local mock Sportmonks server, and no real token or network access.

## Repository layout

```text
server.js              # config, Sportmonks proxy, normalization, cache, fallback, dist server
index.html             # Vite HTML entry
vite.config.js         # Vite config and /api development proxy
src/
  main.jsx             # React entry point
  App.jsx              # page state, data loading, filtering, intervals
  api.js               # /api/movements and /api/status requests
  utils.js             # time, fee, URL, and text helpers
  styles.css           # responsive styles and accessibility support
  components/          # Header, Hero, Notice, StatsGrid, FeedPanel, RecordCard, etc.
public/                # static files copied as-is by Vite (deployment-only /demo/ pages)
scripts/               # offline player sync and import pipeline
test/                  # node --test unit tests
smoke-test.js          # end-to-end tests with a mocked upstream
```

`dist/` is generated by Vite and must not be committed or edited by hand. `server.js` exits at startup if `dist/index.html` is missing.

## Architecture notes

- The HTTP server remains dependency-free and does not read the database. Offline ingestion lives in `scripts/` and is separate from the dashboard.
- `server.js` is intentionally a single file: env loading → config → demo data → normalization → upstream fetch → cache/fallback → static server. Follow that ordering when adding code.
- `server.js` serves `dist/`, not `public/`. Vite copies `public/` into `dist/` during the build.
- The server exposes only `GET`/`HEAD` on `/api/status`, `/api/movements`, and static files under `dist/`. Other methods return `405`.
- `/api` proxying in development is configured in `vite.config.js` and targets `127.0.0.1:4173`.
- Hashed files under `dist/assets/` are served with a long-lived immutable cache; `index.html` and other files use `no-cache`.
- Data is cached in process memory only. Do not introduce external state (databases, Redis, filesystem caches) into the HTTP server unless explicitly requested.
- `demo` and `live` modes are distinct; keep demo records clearly labeled as fictional and never present them as real transfers.
- Rumours are not confirmed transfers. Preserve the `confirmed`/`rumour` distinction, source, and probability in any new code or UI.

## Data contract

Normalized records use: `kind`, `player`, `from`, `to`, `type`, `status`, `announcedAt`, `updatedAt`, `feeText`, `feeMillions`, `feeDisclosed`, `probability`, `sourceName`, `sourceUrl`, `raw`.

- Keep `feeMillions` as `null` when the fee is undisclosed. Never coerce a missing fee to `0`; `0` specifically means a free transfer.
- Respect `SPORTMONKS_FEE_SCALE` (`eur`, `million`, `raw`) when formatting amounts.
- Upstream field mapping is intentionally tolerant (alternative field names via `relation()`); preserve that tolerance when editing normalization.
- The raw upstream record stays in `raw` for traceability.
- Do not change the API response shape without updating the frontend, smoke tests, and both READMEs.

## Frontend conventions

- Use function components and hooks; do not introduce class components or a second state library.
- Keep page-level state in `App.jsx` and pass props down; keep pure helpers in `src/utils.js`.
- Use `useMemo` for derived filtering/sorting and `useDeferredValue` for search input. `RecordCard` is memoized; keep record objects stable when possible.
- React escapes interpolated text automatically. Do not use `dangerouslySetInnerHTML`; validate external links with `safeUrl()` and render only HTTP/HTTPS URLs in `href`.
- Preserve the existing class names and DOM structure unless styles are updated in the same change.
- Preserve accessibility behavior (keyboard activation, focus handling, `aria-*`, reduced-motion support, native `<dialog>`) when touching markup or interactions.
- Do not add npm packages beyond the existing React/Vite toolchain without explicit approval. No CSS framework, router, or state library is needed yet.
- Keep `src/styles.css` as the single stylesheet entry; Vite bundles it automatically.

## Configuration

All server configuration is environment-based and documented in `.env.example` and both READMEs. When adding or changing a server variable:

1. Add it to `.env.example`.
2. Add validation/clamping in the `config` object in `server.js` (use `truthy()` for booleans and `numeric()` with min/max for numbers).
3. Document it in `README.MD` and `README.EN.MD`.
4. Expose it via `/api/status` only if it is non-secret and useful to the frontend.

Shell environment variables take precedence over `.env`. Never expose `SPORTMONKS_TOKEN` to the browser or include it in API responses. Only `VITE_`-prefixed variables reach the frontend; this project needs no frontend secrets.

## Security and repository hygiene

- Never commit `.env`, API tokens, credentials, `dist/`, or the local `.workbuddy-ai/` workspace memory; `.gitignore` covers them.
- Do not weaken the static-file path-traversal check in `serveStatic()`, the `safeUrl()` protocol allowlist, React escaping, or the API security headers.
- Do not log the API token or include it in error messages.
- Do not commit generated artifacts, build output, or new dependencies unless explicitly requested.
- Commit messages use imperative English (e.g., `Add ...`, `Fix ...`), matching existing history.

## Deployment notes

- Build before restarting: `npm ci && npm run build`, then `node server.js` (or restart the systemd unit).
- `dist/` is required at runtime and is not tracked in Git.
- Static demo pages live in `public/demo/` at build time and are copied to `dist/demo/`; they are deployment-only artifacts and are not tracked in the repo.
- The `bwg` systemd unit can keep running `node server.js`; only the release step needs to add the build.
